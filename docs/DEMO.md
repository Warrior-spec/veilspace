# Demo flow

1. Open the Windows app and create an account.
2. Select a folder and place a fictional TXT, DOCX, or text PDF inside it.
3. Watch the file move from queued to published. Open the sanitized document.
4. Open the server website with a second account. Show that only published files appear, with generic filenames.
5. Upload the same document from the second account. Show the cached assessment and unchanged AI request count.
6. Edit the watched file. Show the revision number increase and the previous published version stay available during processing.
7. Upload an unreadable PDF. Show that it stays pending and absent from the shared library.
8. Open the Android app, sign in, and upload a document manually.

Use fictional names and contact details. Explain that aliases are consistent for exact normalized names and that uncertain assessments remain private. The server regenerates text PDFs, so original layout is not preserved.

Submission still needs the team's details, a short screen recording, and the final event submission form. The repository identifies its external libraries and API use.
